# 知枢 Agent 技术报告

## 1. 项目概述
知枢 Agent 是面向中小企业行政人事的企业文档智能流程助手。它将企业内部零散的人事制度文档构建为私有 RAG 知识库，并由任务规划 Agent 自动拆解多步骤人事工作、调用标准化工具生成登记表与待办清单，回答强制基于制度原文并标注来源，解决人事工作"翻文档慢、易凭经验答、表单重复做"的痛点。

## 2. 需求分析
- 真实场景：中小企业无专职知识系统，制度散落在 Word/PDF，新人入职、离职、转正流程靠记忆与口口相传。
- 核心诉求：制度问答要可信（溯源、不编造）、流程要自动化（自动生成表单/待办）、使用要低门槛（自然语言 + 语音）。

## 3. 系统架构
```
用户(浏览器)
  │ 自然语言/语音
  ▼
Next.js App Router (前端 useChat 流式渲染)
  ▼ /api/agent
Agent 编排层 (streamText, maxSteps=3)
  ├─ RAG 检索层：本地向量库召回 Top-K 制度片段
  ├─ 分层提示词：注入知识库上下文 + 安全规则
  └─ MCP 风格工具层：JSON Schema 工具注册与结构化调用
        ▼
智谱 glm-4-flash(对话,免费,支持工具调用) / 智谱 embedding-3(向量化)
```

## 4. 核心模块实现

### 4.1 RAG 文档检索与溯源
`rag.ts` 负责文档解析（txt/md 直读、pdf-parse 解析 PDF、mammoth 解析 Word）、按 ~800 字符切片；`embedding.ts` 调用智谱 embedding-3 得到向量；`vectorStore.ts` 以余弦相似度做 Top-K 检索，并把命中片段的来源文件名随上下文注入提示词，要求模型在回答末尾列出来源，实现可溯源、不幻觉。

### 4.2 Agent 任务规划
`agent.ts` 采用分层系统提示词：先检索知识库，再由模型判断是否需要调用工具；借助 Vercel AI SDK 的 `maxSteps=3` 实现"规划—调用—观察—再回答"的多步循环，完成复杂人事任务。

### 4.3 MCP 风格工具链
`tools.ts` 借鉴 Model Context Protocol 的工具元数据描述思想，对每个工具统一维护名称、功能描述、JSON Schema 入参与执行 handler，并与 AI SDK 的结构化工具调用对接。工具定义与业务逻辑解耦，便于后续扩展请假、报销等人事工具。

### 4.4 多模态输入
前端通过浏览器原生 Web Speech API（`webkitSpeechRecognition`）实现中文语音转文字，零额外模型成本，丰富输入方式。

## 5. 关键设计取舍
- 对话选用智谱 glm-4-flash：免费额度、原生支持函数调用，与 embedding-3 共用一个 key，降低配置成本；OpenAI 兼容协议接入。
- 为保证演示稳定，向量库采用内存 + JSON 持久化，避免独立向量数据库服务依赖，可平滑替换为 Chroma。

## 6. 创新点
1. 面向中小企业行政人事这一未被充分满足的真实场景，把 RAG 从"问答"延伸到"流程执行"（自动生成表单/待办）。
2. MCP 思想的工具注册层 + 结构化工具调用，工具可扩展、可审计。
3. 强制溯源与"无依据拒答"，把 AI 安全可控落到人事合规场景。

## 7. 不足与展望
- 目前为单 Agent 单轮规划，后续可扩展多 Agent 协作与人效指标统计。
- 在线多用户、权限隔离与公网部署可作为下一阶段工作。

## 8. 分工
